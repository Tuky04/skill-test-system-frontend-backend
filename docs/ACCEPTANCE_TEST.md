# ชุดทดสอบรับมอบ

## อัตโนมัติ

- Backend: `npm test`
- Frontend: `CI=true npm run build` (PowerShell ใช้ `$env:CI='true'`)
- Dependency: `npm audit` ใน CI ที่องค์กรอนุญาตให้เชื่อม npm registry

## Manual/E2E ที่ต้องผ่านก่อน production

- สมัครสำเร็จ, ข้อมูลซ้ำ, checksum บัตรผิด, วันเกิดอนาคต, ไม่ consent
- ไฟล์ผิดชนิด/เกินขนาด/signature ปลอม และ rollback ต้องไม่เหลือไฟล์กำพร้า
- ยืนยันอีเมล, ส่งลิงก์ใหม่, ลืมรหัสผ่าน, token หมดอายุ/ใช้ซ้ำ
- นักศึกษา A เปิดข้อมูล/เอกสาร/ใบรับรองหรือสมัครแทน B ไม่ได้
- ส่งเอกสารใหม่ได้เฉพาะสถานะเอกสารไม่ครบและมีประวัติเวอร์ชัน
- สมัครได้เฉพาะช่วงเปิดรับ; ทดสอบพร้อมกันที่ที่นั่งสุดท้ายต้องสำเร็จเพียงจำนวนที่กำหนด
- เปลี่ยนสถานะใบสมัครและเข้าสอบตามลำดับ; ขาดสอบ/ยกเลิกบันทึกคะแนนไม่ได้
- คะแนน 0 เป็นคะแนนจริงได้, คะแนนเกินเต็ม/คะแนนหักเกินผลรวม/ข้อความถูกปฏิเสธ
- staff แก้ผลประกาศแล้วไม่ได้; admin แก้ได้และต้องมี audit
- สมัครซ่อมได้เฉพาะผลประกาศว่าไม่ผ่าน ไม่เกิน `max_attempts`
- เปลี่ยน role/รหัสผ่าน/ปิดบัญชีแล้ว access/refresh token เดิมใช้ไม่ได้
- traversal และ query-string token ใช้ไม่ได้; public uploads ใช้ไม่ได้
- CSV ที่ขึ้นต้น `= + - @` เปิดแล้วเป็นข้อความ ไม่เป็นสูตร
- ใบรับรองข้อมูลคงที่ ตรวจ public ได้ ไม่แสดงเลขบัตรเต็ม เพิกถอนแล้ว invalid และออกใหม่เปลี่ยน verification code
- ส่งคำขอที่มีคุกกี้เสีย (เช่น `Cookie: refresh_token=%`) ไปที่ `/api/auth/refresh` ต้องได้ 401 และเซิร์ฟเวอร์ยังทำงานต่อ
- ตัวจำกัดอัตราแยกกัน: สมัครสมาชิกจนครบโควตา แล้วขอรีเซ็ตรหัสผ่านต้องยังทำได้; เข้าสู่ระบบสำเร็จหลายครั้งไม่ถูกนับเป็นความพยายามล้มเหลว
- ทดสอบบนเครื่องที่ตั้งเขตเวลาเป็น Asia/Bangkok: วันเปิด/ปิดรับสมัครตรงวันที่ที่แอดมินกรอก (วันสุดท้ายยังสมัครได้) และการเปิดหน้าแก้ไขวิชาแล้วบันทึกซ้ำไม่ทำให้วันที่ถอยหลัง
- admin แก้คะแนนที่ประกาศแล้วที่หน้า "แก้ไขคะแนน" ต้องระบุเหตุผล; ถ้าผลใหม่ไม่ผ่านเกณฑ์ ใบรับรองเดิมถูกเพิกถอน; มีแถวใน `score_audit_logs` และ `admin_audit_logs`; นักศึกษาได้รับแจ้ง
- staff แก้คะแนนที่ประกาศแล้วไม่ได้ (ได้ข้อความให้แจ้งผู้ดูแลระบบ)
- กดอนุมัติ/ตรวจเอกสารซ้ำด้วยสถานะเดิม ต้องไม่ส่งอีเมลหรือแจ้งเตือนซ้ำ และการนำใบสมัครที่ถูกปฏิเสธกลับมาเมื่อที่นั่งเต็มต้องถูกปฏิเสธ
- ส่งออก Excel จำนวนมากระหว่างที่ผู้ใช้อื่นใช้งานปกติ: หน้าอื่นต้องไม่ค้าง และเมื่อมีงานส่งออกเกินจำนวนที่กำหนดต้องได้ข้อความให้รอ (HTTP 429)
- เปิดแท็บใหม่หลังล็อกอินแล้ว (ยังไม่ออกจากระบบ) ต้องกู้เซสชันได้โดยไม่ต้องล็อกอินซ้ำ และไม่มี role/ข้อมูลผู้ใช้ค้างใน localStorage
- backup/restore drill ผ่านและ KPI เทียบ SQL อิสระตรงกัน

บันทึก evidence, ผู้ทดสอบ, เวลา, build checksum และผลผ่าน/ไม่ผ่านทุกข้อก่อนลงนามรับมอบ
