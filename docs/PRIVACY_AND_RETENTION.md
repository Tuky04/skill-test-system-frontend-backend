# แนวทางความเป็นส่วนตัวและอายุการเก็บข้อมูล

เอกสารนี้เป็นแนวทางด้านระบบ ไม่ใช่คำปรึกษากฎหมาย องค์กรต้องกำหนดผู้ควบคุมข้อมูล ช่องทางติดต่อ ฐานกฎหมาย และระยะเวลาให้สอดคล้อง PDPA/ระเบียบที่ใช้จริง

## วัตถุประสงค์ที่ระบบใช้ข้อมูล

- พิสูจน์ตัวตนและคุณสมบัติผู้สมัคร
- จัดรอบสอบ บันทึกผล และติดต่อเรื่องการสอบ
- ออก/ตรวจสอบ/เพิกถอนใบรับรอง
- ตรวจสอบย้อนหลังด้านความถูกต้อง ความปลอดภัย และข้อร้องเรียน

หน้า registration บันทึก `privacy_consent_at` และ `privacy_policy_version` เฉพาะเมื่อผู้ใช้เลือกยินยอม ห้าม pre-check checkbox

## หลักการเข้าถึง

- นักศึกษา: เฉพาะข้อมูลและเอกสารของตนเอง
- staff: งานตรวจเอกสาร/ใบสมัคร/การเข้าสอบ/คะแนนตามหน้าที่
- admin: จัดการระบบ รายงาน ผู้ใช้ และใบรับรอง
- การเปิดเอกสารโดย staff/admin ถูกบันทึกใน `admin_audit_logs`

## อายุการเก็บที่ควรกำหนดเป็นลายลักษณ์อักษร

- เอกสารผู้สมัครที่ไม่ผ่าน/ไม่ดำเนินการต่อ: กำหนดช่วงสั้นที่สุดที่กฎหมายและการอุทธรณ์ต้องใช้
- เอกสารผู้เข้าสอบ: เก็บตามระเบียบหน่วยงาน แล้วทำลายทั้งไฟล์หลัก backup และ metadata ตามรอบ
- คะแนน ใบรับรอง และ audit: เก็บตามอายุหลักฐาน/ข้อกำหนดวิชาชีพ
- reset/email verification token: ระบบล้างค่าเมื่อใช้สำเร็จและมีวันหมดอายุ

ควรมี job ที่สร้างรายงานรายการครบกำหนดให้ผู้มีอำนาจอนุมัติก่อนลบ และเก็บ destruction log โดยไม่เก็บเนื้อหาเอกสารที่ถูกลบ

## เหตุข้อมูลรั่วไหล

หยุดการเข้าถึงที่ผิดปกติ, rotate credential, เก็บ log แบบ read-only, ประเมินขอบเขต/ผู้ได้รับผลกระทบ, แจ้งผู้ควบคุมข้อมูลและดำเนินการตามแผน incident response ขององค์กร ห้ามส่งไฟล์จริงหรือ `.env` ผ่านช่องทางที่ไม่ได้รับอนุมัติ
