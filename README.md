# Skill Test System — ชุดแก้ไขและเพิ่มความปลอดภัย

ชุดนี้เป็น source code ที่แก้ไขจากระบบเดิม โดยไม่รวม `.env`, รหัสผ่านจริง, `node_modules`, build output หรือเอกสารส่วนบุคคลของผู้สมัคร

## สิ่งที่แก้แล้ว

- แก้การลงทะเบียนที่จำนวนค่า SQL ไม่ตรงกัน และสร้างรหัสผู้สมัครแบบไม่ชนกัน
- ใช้สถานะเดียวกันทั้งฐานข้อมูล/backend/frontend และแยกสถานะใบสมัคร การเข้าสอบ และการประกาศผล
- ปิด IDOR: นักศึกษาดู สมัครสอบ สมัครซ่อม และเปิดใบรับรองได้เฉพาะข้อมูลของบัญชีตนเอง
- ย้ายเอกสารไปพื้นที่ private ตรวจนามสกุล MIME และ magic bytes จำกัดขนาด ป้องกัน traversal และบันทึกประวัติการเปิดโดยเจ้าหน้าที่
- เก็บเวอร์ชันเอกสารเมื่อส่งใหม่หลังสถานะ “เอกสารไม่ครบ”
- ใช้ access token อายุสั้นและ refresh token แบบ HttpOnly cookie; revoke session เมื่อเปลี่ยน role/รหัสผ่าน/ปิดบัญชี
- เพิ่มยืนยันอีเมล ส่งลิงก์ยืนยันใหม่ ลืมรหัสผ่าน และ reset token แบบ hash/หมดอายุ
- บังคับช่วงรับสมัคร จำนวนที่นั่ง จำนวนครั้งสอบซ่อม และสร้างรอบสอบตามวิชา/วัน/เวลา/สถานที่
- ไม่สร้างคะแนน 0 ก่อนสอบ; ต้องยืนยัน “เข้าสอบ” ก่อนบันทึกคะแนน และบันทึกคะแนน/audit/ประกาศผลใน transaction
- แก้ KPI และ export CSV พร้อมป้องกัน formula injection
- ใบรับรองมีเลขที่/วันออก/รหัสตรวจสอบถาวร ตรวจสอบสาธารณะโดยเปิดเผยข้อมูลขั้นต่ำ และรองรับเพิกถอน/ออกใหม่
- เพิ่ม CORS allowlist, rate limit, security headers, request ID, health check, graceful shutdown และ error handler กลาง
- เพิ่มความยินยอมข้อมูลส่วนบุคคลและเก็บเวอร์ชันประกาศที่ยอมรับ
- เพิ่ม migration, schema เปล่าที่ไม่มีข้อมูลจริง, unit tests และคู่มือปฏิบัติการ

## โครงสร้าง

- `backend/` API, migration และชุดทดสอบ
- `frontend/` React web application
- `skill_test_system.sql` schema สำหรับติดตั้งใหม่ (ไม่มีบัญชีตัวอย่างและไม่มีข้อมูลบุคคล)
- `docs/` คู่มือติดตั้ง ย้ายระบบ ความเป็นส่วนตัว สำรองข้อมูล และทดสอบรับมอบ
- `EMAIL_SETUP_TH.md` คู่มือตั้งค่าการยืนยันตัวตน อีเมลแจ้งเตือน และการทดสอบ SMTP

## เริ่มต้นแบบย่อ

1. ติดตั้งฐานข้อมูลใหม่ด้วย `skill_test_system.sql` หรือทำตาม `docs/MIGRATION.md` หากมีข้อมูลเดิม
2. ใน `backend/` คัดลอก `.env.example` เป็น `.env` แล้วเปลี่ยนทุกค่า secret/credential
3. รัน `npm ci`, `npm test`, `npm run create-admin`, `npm run create-staff`, แล้ว `npm start`
4. ใน `frontend/` คัดลอก `.env.example` เป็น `.env`, ตั้ง API URL, รัน `npm ci` และ `npm run build`
5. วาง frontend build หลัง HTTPS reverse proxy และให้ `/api` ชี้ไป backend

อ่านขั้นตอนละเอียดและ checklist ก่อนเปิดระบบใน [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)

## ข้อจำกัดที่ต้องจัดการตามสภาพแวดล้อมจริง

- ใบรับรองเป็นหน้า HTML สำหรับพิมพ์/Save as PDF จากเบราว์เซอร์ ระบบไม่ได้ติดตั้ง PDF renderer ฝั่ง server
- ระบบตรวจชนิดไฟล์และลายเซ็นไฟล์แล้ว แต่ antivirus/object storage/email queue ต้องเชื่อมบริการขององค์กร
- นโยบายอายุการเก็บข้อมูลในเอกสารเป็นค่าแนะนำ ต้องให้ผู้ควบคุมข้อมูลและฝ่ายกฎหมายอนุมัติก่อนใช้จริง
- ต้องใช้ HTTPS ใน production มิฉะนั้น cookie และข้อมูลส่วนบุคคลไม่ควรถูกส่งผ่านเครือข่าย
